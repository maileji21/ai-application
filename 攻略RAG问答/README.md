# 旅游攻略 RAG 问答

基于自采的 6 城 226 个景点攻略，做一个能落地的检索增强问答：问"成都哪个古镇免费、怎么去"，它从攻略库里检索相关段落，再让大模型基于检索结果作答，每句带来源编号。

**为什么做这个**：大模型不知道我本地这份攻略库，直接问它门票价格只会编。RAG 解决的就是"模型不知道的私有知识"——先把相关资料找出来塞进 prompt，答案有据可查。

## 管线

```
景点 CSV（226 篇）
   → 分块（300 字 / 50 字重叠，块内带景点名与门票，保证可独立回答）
   → 向量化（智谱 embedding-3，2048 维）
   → 余弦相似度检索 top-3
   → 拼 prompt（只允许依据资料回答 + 单编号引用）
   → GLM-4-Flash 生成 → 解析引用编号，只展示真实来源
```

## 实测指标

| 指标 | 数值 |
|---|---|
| 语料规模 | 6 城 226 篇景点攻略（226 块） |
| 向量维度 / 索引耗时 | 2048 维 / 10.3s（缓存复用） |
| 单次检索延迟 | 0.26-0.38s |
| 检索召回（10 题人工标注） | **Recall@1 = 90%，Recall@3 = 100%** |
| 语料外问题（问广州） | 最高相似度 0.356，低于阈值 0.40，**不调模型直接拒答** |

## 设计要点

- **分块带元信息**：每块开头拼上"景点／城市／地址／门票"，语义切断了也能独立回答"门票多少"这类问题
- **引用可核对**：prompt 要求每句只标一个最相关资料编号；代码再解析回答里的【n】只输出真实引用来源，模型乱标时能看出来
- **阈值拒答**：实测语料内问题相似度 0.41-0.60、语料外 0.34-0.36，据此设 0.40 阈值，低于阈值直接回"语料中没有相关内容"，省一次模型调用也避免幻觉
- **可评测**：`eval_retrieval.py` + 10 条人工标注问题，只测检索层不调大模型，改动分块或模型后能快速回归

## 怎么跑

```bash
pip install requests numpy
set GLM_API=你的智谱APIKey
python rag_demo.py --rebuild --ask "杭州有哪些免费的博物馆"
python rag_demo.py --ask "成都哪个古镇免费，怎么去" --topk 3
python eval_retrieval.py --topk 3        # 检索质量评测
```

## 示例

```
问题：成都哪个古镇免费，怎么去
检索 3 条（0.27s）：
  【1】安仁古镇（成都） 相似度 0.533
  【2】洛带古镇（成都） 相似度 0.530
  【3】黄龙溪古镇（成都） 相似度 0.510
回答：安仁古镇和洛带古镇都免费，可公交或地铁到安仁古镇站或洛带古镇站下车。
引用来源：【1】安仁古镇、【2】洛带古镇

问题：广州有哪些值得去的景点
最高相似度 0.356 < 阈值 0.4：语料中没有相关内容，不调用大模型，直接拒答。
```

## 已知局限

- 只做纯向量检索，**没有 BM25 混合检索和重排**——"景点名字精确命中"这类查询，向量检索不如关键词检索稳，这是下一步升级方向
- 语料只有 226 篇，规模小，检索延迟和召回不能代表大规模场景
- 评测集 10 题是手工标注，样本小，只能看趋势不能当严格 benchmark
- 数据来自高德 POI + 大模型生成的攻略（见仓库根目录的项目一），门票为参考价
